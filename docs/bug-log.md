# Bug log (QA of the test school)

Found by walking the app as each role on the **test project** (see `docs/qa-test-school.md`). Status: **fixed** (committed, not yet pushed), **open**, or **not a bug** (checked and intended).
Severity: **high** (a feature fails or data could be exposed), **medium** (a feature is slow, confusing or wrong in a common case), **low** (cosmetic or rare).

| # | Where | What happened | Severity | Status |
|---|---|---|---|---|
| B-001 | Integrity dashboard (HOD Analytics > Integrity, school admin) | The page fetched **every exam session with every answer** and filtered on screen. On a test school with 178 sittings it made the database time out (error 57014, 15 to 30 seconds, then a blank page). A real school with thousands of sittings would never load it. | high | **fixed**: asks the database only for flagged essay answers (one query, about 1.2 seconds, flagged answer still shown) |
| B-002 | Every page | Each page asks the sign-in service "who is this?" 8 to 10 times (one call per component), about 1 second each on this connection. Slows every page load, most on phones. | low | open (needs one shared user lookup) |
| B-003 | Smart Learning menu (teachers, heads of department) | **Report Absence**, **My Cover** and **Substitution** opened pages that belong to Smart Assess, so the menu jumped to Smart Assess and its Home item. | B-004 | Menus in every portal | A page with no menu item of its own (an exam you opened, a student, absence) lit the **Home** item, which looked like being sent back to the home page. | B-009 | Draft exams, exam questions, exam-to-class links (database rules) | **A student, using the app's own database connection (not the normal screens), can create an exam, mark it published, link it to their class, and add questions; another student in that class can then see it.** The rules on `draft_exams`, `questions` and `draft_exam_class_groups` check only "you created it", not that you are staff. Found 2026-10-07 with a probe; probe rows were deleted. The normal student screens do not offer this. | **high** | **open, waiting for your go-ahead.** Proposed fix: add the same staff-role check as migration 094 to those three rules (and review `report_card_comments` and the other "own rows" rules), then re-run the probe. |
| B-010 | Database speed (every page that reads or writes questions, exam sittings, sessions) | **The database spends a long time just planning each request because of the row-level security rules**: reading `questions` takes 150 to 200 ms of planning, updating `questions` about 410 ms, updating an exam sitting 250 ms, reading `exam_sessions` 75 to 95 ms (a simple read of `profiles` or `learning_lessons` takes under 10 ms). On this test project one such request is fine, but several at once are not: **six question updates sent together all timed out** (error 57014, after 9 s) and a page that makes many requests can hang. Visible effects found: the integrity dashboard timing out (B-001), and the HOD's **Send feedback** and the comment-saving step of **Approve** failing (B-011). A whole class submitting at once, or a busy exam day, would hit the same limit; how soon depends on the size of the database server (this one is the small test size; Manchester's may be larger). | **high** (for exam day and scale) | **open, waiting for your go-ahead.** Proposed fix: simplify the rules on `questions`, `draft_exams`, `exam_sessions` (use one fast helper function per rule instead of several nested lookups, and look up the signed-in person once per request), then re-measure; plus check what size server Manchester runs on. This is a careful change to the rules that protect student data, so I would test it on the sandbox and the test project before it goes anywhere near Manchester. |
| B-011 | HOD exam review (Send feedback, and Approve's comment step) | Saving the HOD's comments on questions **fails silently** (the question updates time out, B-010; and the database has no rule that lets a head of department update `questions` at all on this project). Check whether Manchester has the missing rule (the HOD portal migrations 050 to 052 may have added it there). | high for the live demo ("vet and publish") | **open, waiting for your go-ahead.** Proposed fix: an explicit message when saving fails, a progress indicator, and (if missing) the rule that lets the HOD save comments. |

## Checked and not a bug
- `cancel_teacher_absence` returns an error on the report-absence and substitution pages: it is a deliberate "is this installed?" check.
- `/principal/ai-tutor` 403 on school settings and `/school-admin/library` 403: both are school switches that are off in the test school.
- Pages that redirect (`/supervisor/classes` to classrooms, `/supervisor/exams` to the teacher's tests, `/teacher/vetting` to the home page for a non-vetting teacher, and similar): intended.
- The pages that redirect (listed above) show a developer-mode-only warning in the browser console ('cannot have a negative time stamp'). It comes from the Next.js development server and does not appear on the live site.
- Phone width: all 124 pages in every role open without sideways scrolling.
